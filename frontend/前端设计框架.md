## 1. 目标与非目标

### 1.1 目标

- 以现有后端接口为准，搭建可长期维护的前端骨架与页面规格。
- 权限在路由层统一拦截，不依赖隐藏按钮。
- 服务端状态、幂等、乐观锁、服务端时间、整数分金额、Asia/Shanghai 展示等契约一次封装，页面不重复处理。
- 四套布局覆盖用户端、用户中心、管理端、认证页。

### 1.2 非目标

- 不做 SSR/SEO（与一期排除项一致）。
- 不做移动端专项设计，桌面优先。
- 不做专栏、电子书、直播、绑定手机号、免费试看；`frontend/img` 中对应截图仅作视觉参考。
- 不改真实支付，前端只调模拟支付接口。

## 3. 架构总览

```text
浏览器
  └─ React SPA（Vite 构建）
       ├─ React Router（四套布局 + 路由守卫）
       ├─ TanStack Query（服务端状态：缓存/失效/重试）
       ├─ Zustand（会话、UI）
       └─ axios 实例（信封解包/错误归一/幂等键/凭据）
             │  Cookie: connect.sid（HttpOnly + SameSite=Lax）
             ▼
        /api/v1（开发经 Vite 代理，生产经 Nginx 同域反代）
```

关键原则：

1. 服务端数据只有一份真源，存在 Query 缓存；Zustand 不复制列表数据。
2. 所有写操作先二次确认，取消不写数据且保留表单内容。
3. 前端不计算价格、库存、分数；只展示服务端结果。
4. 倒计时与考试截止时间以服务端时间为准。
5. 图片只持久化图片 key、音视频只持久化媒体 key，展示 URL 由后端生成（见 §7）。

### 5.2 守卫顺序

```ts
// 路由守卫：按优先级依次判定，命中即返回目标地址
function resolveRedirect(
  user: SessionUser | null,      // 当前会话用户，未登录为 null
  meta: RouteMeta,               // 目标路由的权限元信息
  path: string,                  // 目标完整路径（含 query）
): string | null {
  if (user?.role === 'admin' && !path.startsWith('/admin')) return '/admin'; // 管理员隔离
  if (meta.requiresAuth && !user) return `/login?redirect=${encodeURIComponent(path)}`; // 未登录
  if (meta.roles && user && !meta.roles.includes(user.role)) return '/403'; // 角色不符
  return null; // 放行
}
```

补充规则：

- 启动时调用一次 `GET /auth/me`，结果进 Query 缓存 `['auth','me']` 与 `session` store；失败按未登录处理。
- 管理员访问任何用户端路由（包括浏览器后退到 `/`）统一重定向 `/admin`。
- 管理员不使用用户端 `redirect`，不会被带入购买或学习流程。
- 登录成功：admin → `/admin`；user → `redirect` 优先，否则 `/user`。
- 注册成功不自动登录，跳 `/login` 并提示「注册成功，请登录」。
- 任意接口返回 2001：清会话缓存 → 跳 `/login?redirect=<当前地址>`。
- 2002：跳 `/403`。

## 6. API 集成层

### 6.1 axios 实例

- `baseURL = import.meta.env.VITE_API_BASE ?? '/api/v1'`
- `withCredentials: true`（开发同源代理，生产同域反代）
- 请求头统一 `Accept: application/json`；上传使用 `multipart/form-data`
- 响应解包：`code === 0` 返回 `data`；否则抛 `ApiError`

```ts
// 响应拦截器：解包统一信封，非 0 业务码转为 ApiError
client.interceptors.response.use(
  (response) => {
    const envelope = response.data as Envelope<unknown>; // 后端统一响应包
    if (envelope.code !== 0) {
      throw new ApiError(envelope.code, envelope.message, envelope.data, envelope.requestId, response.status);
    }
    return envelope.data; // 页面只拿 data
  },
  (error) => Promise.reject(normalizeAxiosError(error)), // HTTP 层错误归一
);
```

`ApiError` 字段：`code`、`message`、`data`（后端 `details`，如屏蔽词命中数组）、`requestId`、`status`。

### 6.2 错误码到 UI 动作

| code | 前端动作 |
| --- | --- |
| 1001 | 表单/接口内联提示 `message` |
| 1002 | 空态或 404 组件 |
| 1004 | 上传组件提示「图片不能超过 2MB」 |
| 1005 | toast「操作过于频繁，请稍后再试」 |
| 2001 | 清会话，跳登录并带 `redirect` |
| 2002 | 跳 `/403` |
| 2003 | 登录表单统一提示「邮箱或密码错误」 |
| 3001 | 课程不存在空态 |
| 3002 | 提示未购买，跳课程详情 |
| 4001 / 5003 | 内联提示库存不足/已达限购 |
| 4002 | 提示优惠券不可用，重取价格预览 |
| 4003 | 提示已购买，跳学习页 |
| 4004 | 视为重复提交，静默重取首次结果 |
| 5001 / 5002 | 内联提示团已满/活动未开始 |
| 6001 | 跳考试成绩页 |
| 6002 | 提示考试已结束，返回列表 |
| 7001 | 表单内列出 `error.data` 中全部命中词 |
| 409 | 版本冲突弹窗，提示刷新后重试 |
| 5xx / 网络 | toast + 可复制的 `requestId`，GET 自动重试一次 |

### 6.3 幂等

创建类 POST 必须携带 `Idempotency-Key`，长度 8–128。

```ts
// 幂等键生成：每次用户意图生成一次，重试复用，成功后重置
function newIdempotencyKey(): string {
  return crypto.randomUUID(); // 36 字符，满足 8–128 要求
}
```

`useIdempotentMutation` 行为：

- 提交前若无 key 则生成并保存到 ref；请求失败且为网络/5xx 时重试沿用同一 key。
- 成功后清空 key。
- 请求进行中按钮 `loading` 且禁用，防重复点击。
- 适用接口：创建订单、支付、领券、发起/加入拼团、秒杀购买、发帖、评论、回复、管理端所有创建类 POST。

### 6.4 乐观锁

- 管理端课程、优惠券、活动、考试编辑表单携带详情返回的 `version`。
- 收到 409：弹窗「内容已在其他页面被修改，请刷新后重试」，提供「刷新」按钮重取详情；不自动覆盖。
- 保存成功后重取详情并刷新列表。

### 6.5 分页

- 查询参数 `page`（从 1）、`pageSize`（默认 20，最大 100）。
- 响应 `{ items, total, page, pageSize }`。
- AntD Table 与列表统一用 `usePagination`。

### 6.6 金额

- 全链路整数分（`priceCents`、`paidCents` 等）。
- `MoneyText`：`¥` + 两位小数；原价可用删除线样式。
- `MoneyInput`：输入元、两位小数，内部转为分提交；禁止负值；售价不得高于原价由表单规则与后端双重校验。

### 6.7 时间与服务端时钟

- 响应时间为 ISO 8601 UTC；展示统一 `dayjs.utc(v).tz('Asia/Shanghai')`。
- `useServerClock` 从响应 `Date` 头计算偏移，`now()` 返回校准后的服务端时间；每 60 秒校正一次。
- 所有倒计时（拼团、秒杀）与考试截止时间使用 `now()`；到期后重取数据或触发交卷，不以客户端时钟为准。
- 若前后端跨域部署，需后端暴露 `Date` 头或提供时间接口；推荐同域反代。

### 6.8 Cookie / CSRF / CORS

- 会话 Cookie 默认名 `connect.sid`，HttpOnly + SameSite=Lax，前端不可读。
- 后端当前未实现 CSRF token；前端统一 JSON 提交 + `withCredentials`。若后端后续加 token，在请求拦截器补 `X-CSRF-Token`，页面无感知。
- 开发：Vite `server.proxy` 将 `/api` 转发到 `http://localhost:3000`，避免 CORS。
- 生产：Nginx 同域反代前端静态资源与 `/api`；跨站部署会导致 SameSite=Lax 的会话 Cookie 不发送。

## 7. 图片与文件契约（已决）

**决策：前端只持久化图片/媒体 `key`，后端读取时生成展示地址（图片给公开 URL、音视频给短期签名 URL）。**

### 7.1 上传

- 接口：`POST /api/v1/files/upload`，字段名 `file`，`multipart/form-data`。
- 返回：`{ key: string, url: string }`，`url` 为公开地址（`PUBLIC_BASE_URL + /uploadFiles/ + key`），仅用于即时预览。
- 音视频上传：`POST /api/v1/admin/files/{video|audio}`（仅管理员），返回 `{ key, url, mimeType, size }`；`url` 为默认 4 小时签名地址。
- 前端限制：PNG/JPEG/WebP，单张 ≤2MB；上传前预检类型与大小，服务端再做 magic bytes 校验与重编码。
- 失败映射：1004 → 「图片不能超过 2MB」；其他按 §6.2。

### 7.2 存储与读取

| 场景 | 存储 | 读取响应 | 前端 |
| --- | --- | --- | --- |
| 课程封面 | `cover_url` 存 key | 新增 `coverKey`（原始 key）+ `coverUrl`（公开 URL） | 展示用 `coverUrl`，编辑回写用 `coverKey` |
| 用户/作者头像 | `avatar_url` 存 key | 新增 `avatarKey` + `avatarUrl`（公开 URL） | 展示用 `avatarUrl`，编辑回写用 `avatarKey` |
| 富文本图片 | `<img data-key="key">`，`src` 可为 key | 后端把 `src` 重写为公开 URL，保留 `data-key` | 编辑器保存前 `src = img.dataset.key || img.src` |
| 视频/音频章节 | `content` 存媒体 key | 返回签名 URL | 播放器直接用 |

兼容规则：历史 `http(s)` 数据原样返回，不重写、不报错；`coverKey/avatarKey` 为 `null` 时，编辑回写仍用 `coverUrl/avatarUrl`。

### 7.3 后端改造清单（已实施）

实现位置：`src/common/utils/media.util.ts`（key 识别/收集/重写）、`StorageService.resolveUrl` / `resolveRichHtml`、`StorageModule` 全局导出；`openapi.yaml` 已补 `coverKey`/`avatarKey`。

1. `common/utils/sanitize.util.ts`：`img` 允许属性增加 `data-key`。
2. 读取路径统一解析：课程公开/管理详情、章节正文、帖子详情与信息流、用户资料、认证 `me`；图片重写为公开 URL、音视频生成短期签名 URL。
3. 响应增加派生字段：`coverKey`、`avatarKey`（无则 `null`）。
4. 富文本读取时重写 `<img data-key>` 的 `src` 为公开 URL，保留 `data-key`。
5. 音视频签名有效期默认 4 小时，`UPLOAD_MEDIA_TTL_SECONDS` 可配；图片为公开地址，无签名过期问题。

### 7.4 前端处理

- `lib/image-url.ts`：`isStorageKey(value)` 判断是否 http(s)；`resolveImageUrl(value, signed?)` 统一取展示地址。
- 图片 `onError` 只触发一次父资源重取（音视频签名过期时避免裂图/播放失败）。
- 封面/头像上传组件返回 `{ key, url }`，表单只提交 key；预览用临时 `url`。

## 9. 公共组件契约

| 组件 | 职责 | 关键约束 |
| --- | --- | --- |
| `AppTable<T>` | 列表、分页、加载、空态、错误重试 | 列定义泛型；统一 `page/pageSize/total` |
| `ConfirmAction` | 写操作二次确认 | `onConfirm` 异步；取消不触发；确认期间禁用 |
| `Countdown` | 拼团/秒杀/考试倒计时 | 传入截止 ISO 与 `useServerClock`；到期回调一次 |
| `MoneyInput` | 元↔分转换 | 仅数字与一个小数点，最多两位小数，非负 |
| `MoneyText` | 金额展示 | 整数分；可选原价删除线 |
| `StatusTag` | 状态标签 | 课程/订单/团/活动/考试状态到文案与颜色的集中映射 |
| `RichTextEditor` | 富文本编辑 | 标题、加粗、斜体、列表、链接、图片、表格；表格 ≤20×20；Word 粘贴清理；保存时图片取 `data-key` |
| `RichTextViewer` | 富文本展示 | 后端已净化，前端再用 DOMPurify 白名单过滤一次 |
| `ImageUploader` | 图片上传 | 预检类型/大小；返回 `{key,url}`；表单提交 key |
| `PageHeader` | 页面标题与操作区 | 管理端统一面包屑 |
| `EmptyState` | 空态 | 文案 + 可选操作 |
| `ErrorBoundary` | 路由级兜底 | 展示 `requestId` 与重试 |

Hooks：

- `useServerClock`：返回 `offset` 与 `now()`。
- `useIdempotentMutation`：幂等键生命周期、提交中状态。
- `usePagination`：页码与页大小，越界回退。
- `usePermission`：角色判断，仅用于展示，不作为安全边界。
- `useCountdown`：基于服务端时间的剩余毫秒。

## 11. 表单与校验

前端校验与后端 DTO 保持一致，后端仍是最终裁决。

| 字段 | 规则 |
| --- | --- |
| 邮箱 | 标准邮箱格式；注册时重复由后端 1001 提示 |
