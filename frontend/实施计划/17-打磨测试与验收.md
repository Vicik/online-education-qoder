### 数据隔离与可重跑

- 每个用例默认独立 `BrowserContext`，Cookie 不共享；同一用例内需要双角色时显式创建第二个上下文。
- 购买、考试使用**每次新注册**的邮箱，避免「已购买」「已有 attempt」阻塞重跑。
- 管理端创建的课程、题目、考试名称带 `uniqueSuffix()`，断言只认本次生成的内容。
- 社区用例使用演示用户，在用例末尾删除帖子，级联清理评论与回复。
- 不依赖列表顺序与自增 id（课程详情固定用 `id=1` 除外）；考试 id 从管理端「编辑」链接的 href 提取。

优先 `getByLabel` / `getByRole` / `getByPlaceholder`，文本必须与本计划各步骤实现中的中文文案一致；只有动态总分与排序行保留 `data-testid`（`exam-total`、`question-order-*`）。禁止用 CSS 类名或 AntD 内部结构定位。

`src/components/common/ErrorBoundary.tsx`（替换渲染部分，类结构不变）：

```tsx
import { Button, Result, Space } from 'antd';
import { Component, type PropsWithChildren } from 'react';
import { ApiError } from '@/api/errors';

// 路由级错误边界：展示错误摘要、requestId、重试与首页入口
export class ErrorBoundary extends Component<PropsWithChildren, { error: Error | null }> {
  // 捕获到的渲染错误
  state = { error: null as Error | null };

  // 子组件抛错时转为状态
  static getDerivedStateFromError(error: Error) {
    return { error };
  }

  render() {
    if (this.state.error) {
      // 可追踪的请求编号（非接口错误时为空）
      const requestId =
        this.state.error instanceof ApiError ? this.state.error.requestId : undefined;
      return (
        <Result
          status="error"
          title="页面出错了"
          subTitle={requestId ? `请求编号：${requestId}` : '请稍后重试'}
          extra={
            <Space>
              <Button type="primary" onClick={() => window.location.reload()}>
                重试
              </Button>
              <Button onClick={() => window.location.assign('/')}>返回首页</Button>
            </Space>
          }
        />
      );
    }
    return this.props.children;
  }
}
```

```ts
/// <reference types="vitest/config" />
import { fileURLToPath, URL } from 'node:url';
import react from '@vitejs/plugin-react';
import { defineConfig } from 'vite';

// 第三方依赖分包：把低频编辑器与 UI 库从入口拆开，避免首屏加载编辑器
function manualChunks(id: string): string | undefined {
  // 非依赖模块交给 Rollup 默认处理
  if (!id.includes('node_modules')) return undefined;
  // Tiptap / ProseMirror / 净化库只在编辑与展示富文本时加载
  if (id.includes('@tiptap') || id.includes('prosemirror') || id.includes('dompurify')) {
    return 'editor';
  }
  // AntD 及其 rc-* 组件
  if (id.includes('antd') || id.includes('@ant-design') || id.includes('rc-')) {
    return 'antd';
  }
  // 请求、缓存、状态、时间
  if (
    id.includes('@tanstack') ||
    id.includes('axios') ||
    id.includes('zustand') ||
    id.includes('dayjs')
  ) {
    return 'data';
  }
  // React 运行时（放在 tiptap 判断之后，避免误吞 @tiptap/react）
  if (id.includes('react') || id.includes('scheduler')) {
    return 'react';
  }
  return undefined;
}

export default defineConfig({
  plugins: [react()],
  resolve: {
    // 别名：@ 指向 src，避免深层相对路径
    alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) },
  },
  server: {
    // 开发代理：/api 转发到本地后端，规避 CORS 与 SameSite 会话问题
    proxy: { '/api': { target: 'http://localhost:3000', changeOrigin: true } },
  },
  test: {
    // 单元/组件测试使用 jsdom
    environment: 'jsdom',
    globals: true,
    setupFiles: ['./tests/setup.ts'],
    css: true,
    coverage: { reporter: ['text', 'lcov'] },
  },
  build: {
    rollupOptions: {
      output: { manualChunks },
    },
  },
});
```

- [ ] **3.3 体积守卫脚本** `frontend/scripts/check-bundle.mjs`

```js
// 产物体积守卫：任一 JS 分块 gzip 后超过阈值即失败，防止无意引入大依赖
import { readdirSync, readFileSync } from 'node:fs';
import { gzipSync } from 'node:zlib';
import { join } from 'node:path';

// 产物体积上限（KB，gzip 后）：单块 500、合计 1200
const LIMITS = { total: 1200, chunk: 500 };
// Vite 构建产物目录
const ASSETS_DIR = 'dist/assets';

// 构建后的全部 JS 文件
const jsFiles = readdirSync(ASSETS_DIR).filter((file) => file.endsWith('.js'));
if (jsFiles.length === 0) {
  console.error('未找到构建产物，请先运行 npm run build');
  process.exit(1);
}

// 累计 gzip 体积
let totalKb = 0;
// 单文件统计
const rows = jsFiles.map((file) => {
  // 单文件 gzip 后大小（KB，向上取整）
  const gzipKb = Math.ceil(gzipSync(readFileSync(join(ASSETS_DIR, file))).length / 1024);
  totalKb += gzipKb;
  return { file, gzipKb };
});

// 按体积降序输出，便于定位回归
rows.sort((a, b) => b.gzipKb - a.gzipKb);
for (const row of rows) {
  console.log(`${row.file}\t${row.gzipKb} KB`);
}
console.log(`合计\t${totalKb} KB`);

// 单块超限
const oversized = rows.filter((row) => row.gzipKb > LIMITS.chunk);
if (oversized.length > 0) {
  console.error(
    `以下分块超过 ${LIMITS.chunk} KB：${oversized.map((row) => row.file).join(', ')}`,
  );
  process.exit(1);
}

// 总量超限
if (totalKb > LIMITS.total) {
  console.error(`JS 总体积 ${totalKb} KB 超过上限 ${LIMITS.total} KB`);
  process.exit(1);
}
```

## 已知边界

- **E2E 以 CI 为准**：本机 Docker 不可靠，核心链路无法在本机稳定跑通；未在 CI 实际运行的结论必须写「未执行」。
- **E2E 不含 MinIO**：核心链路不上传图片；图片 key/签名恢复由组件与后端测试覆盖。
- **E2E 不含拼团/秒杀/优惠券**：时间窗口、库存与限领状态难以在单次串行运行中稳定构造；由组件测试覆盖规则，E2E 不重复。
- **不引入 axe**：本步只做键盘与语义标签检查，不新建视觉回归或自动可访问性扫描基线；如后续引入需单独评估依赖与基线维护。
- **体积上限是回归守卫**：阈值只防大幅膨胀，不代表性能达标；Lighthouse/Core Web Vitals 未纳入本步。
- **管理端工作台仍为占位**：统计接口未实现，验收项不包含工作台真实数据。
