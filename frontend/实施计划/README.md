## 2. 全局约束（每步都适用，速查）

- **技术栈已定，不得替换**：React 19 + Vite 7 + TypeScript 5；React Router 7（library 模式）；Ant Design 5 + `@ant-design/v5-patch-for-react-19`；TanStack Query 5；Zustand 5（仅会话与 UI）；axios 1；dayjs（`utc` + `timezone`）；Tiptap 3（表格/图片/Word 粘贴清理）；DOMPurify；Vitest 3 + React Testing Library + MSW 2；Playwright；ESLint 9 flat config + Prettier；`openapi-typescript` 生成类型。
- **直连后端，无 Mock 数据层**：`baseURL = /api/v1`，开发经 Vite 代理到 `http://localhost:3000`，生产同域反代；`withCredentials: true`；会话 Cookie `connect.sid`（HttpOnly + SameSite=Lax，前端不可读）。
- **统一响应包**：`{ code, message, data, requestId }`，`code=0` 成功；非 0 抛 `ApiError`。错误码到 UI 动作的映射以设计框架 §6.2 为准；2001 统一清会话并跳登录（带 `redirect`），2002 跳 `/403`。
- **幂等**：创建类 POST 必带 `Idempotency-Key`（8–128 字符，`crypto.randomUUID()` 36 字符）；同一用户意图重试复用同一 key，成功后重置；提交中按钮禁用。
- **乐观锁**：管理端课程、优惠券、拼团、秒杀、题目、考试的编辑请求必须携带详情返回的 `version`；收到 409 只提示刷新，不自动覆盖。
- **分页**：`page` 从 1，`pageSize` 默认 20、最大 100；响应 `{ items, total, page, pageSize }`；列表统一走 `usePagination`。
- **金额**：全链路整数分；展示 `¥` + 两位小数；输入以元录入、内部转分提交；禁止负值；售价不得高于原价（前端表单规则 + 后端双重校验）。
- **时间**：接口时间为 ISO 8601 UTC；展示统一 `dayjs.utc(v).tz('Asia/Shanghai')`；拼团/秒杀/考试倒计时一律使用服务端校准时间 `useServerClock().now()`，到期重取数据或触发交卷，不以客户端时钟为准。
- **图片契约**：前端只持久化对象存储 `key`；展示用后端签名的 `coverUrl`/`avatarUrl`；富文本 `<img data-key="key">`，保存前把 `src` 回写为 `data-key`；签名过期由图片 `onError` 触发一次父资源重取。
- **权限在路由层**：`requiresAuth` / `roles` 元信息由统一守卫拦截，不依赖隐藏按钮；管理员访问任何非 `/admin` 路由统一重定向 `/admin`；普通用户访问 `/admin/*` 跳 `/403`。
- **写操作先确认**：所有业务写入（创建、保存、发布、下架、启停、取消、删除、支付、领券、参团、交卷）先二次确认；取消后不写数据且表单内容保持不变。
- **范围红线**：不做 SSR/SEO、移动端专项、专栏、电子书、直播、绑定手机号、免费试看、真实支付、搜索/筛选（后端无参数）；`frontend/img` 中对应截图只作视觉参考。
- **类型与文件**：业务类型一律来自 `src/api/schema.d.ts` 或基于它的派生类型，不手写重复 DTO；单文件超过约 300 行拆分子组件或 hooks；跨 feature 只通过 `components/common` 与 `api/` 通信。
- **代码注释**：所有非测试源码按工作区约定为每个函数、每个变量补注释；测试文件豁免。
- **测试分层**：单元/组件测试（Vitest + RTL + MSW）本机可跑；Playwright E2E 依赖真实后端（PostgreSQL + Redis；图片链路另需 MinIO）与种子数据，本机 Docker 不可靠，**E2E 以 CI 或具备后端环境时的结果为准**；未执行的验证项必须在提交说明/交付记录中如实写明。
- **git**：仓库已初始化；当前 worktree 为 detached HEAD，执行前先由用户确认功能分支，不直接向 `main` 提交；是否推送、开 PR、合并由用户决定。提交粒度为一个子任务一次，不攒大提交。

## 5. 执行约定

1. **TDD 循环**：每个子任务按「写失败测试 → 运行确认失败 → 最小实现 → 运行确认通过 → 提交」执行；步骤文档已给出测试主体，允许按需补断言。
2. **提交规范**：`feat(scope): 描述` / `test(scope): 描述` / `fix(scope): 描述` / `chore: 描述`；完成一个子任务提交一次。
3. **契约对齐**：页面只消费 `src/api/*` 导出的函数；请求/响应字段以 `schema.d.ts` 为准；发现契约歧义先改设计文档。
4. **接口（模块）约定**：后置步骤消费前置步骤产出的 API 函数、组件、hooks，名称与签名以各步骤「接口契约」为准，不得擅自改名。
5. **每步验收**：满足该步「完成标准」（本机命令 + CI 命令）；E2E 未执行时如实记录依赖缺失。
6. **生成物**：`src/api/schema.d.ts` 由 `npm run gen:api` 生成并提交；CI 运行生成后执行 `git diff --exit-code`，禁止手改。
7. **未验证声明**：任何未运行或无法运行的测试，在提交说明与交付记录中写明原因，不得口头声称通过。
